# PRD Step1. 문제 정의 분석 (5W1H)

## WHO — 누가 이 문제를 겪고 있는가?

### 주요 해결 대상: 주식회사 제주소금

주식회사 제주소금(대표 고경민, 2025년 3월 설립)은 **세계적 희소자원인 용암해수 기반 미네랄 조절 기술**을 보유한 스타트업입니다. 70년에 걸쳐 확보한 기술력으로 나트륨 함량은 24.1g(100g당)으로 낮추면서 마그네슘 6,370mg, 규소 90mg 등 미네랄을 압도적으로 높인 프리미엄 소금을 생산하고 있습니다. 현재 제주용암소금(7,000원), 제주용암프리미엄솔트(8,000원), 제주용암톳소금(12,000원) 등 3가지 B2C 제품을 판매 중입니다.

그러나 이 기업이 직면한 핵심 문제는 **"기술력은 있지만, 그 기술을 소비자에게 매력적으로 전달할 체계적 콘텐츠 생산 능력이 없다"**는 점입니다. 현재 콘텐츠는 산발적·일회성으로 만들어지고 있으며, 브랜드 정체성, 캐릭터, 스토리텔링 같은 체계적 프레임워크 없이 "한 번 만들고 끝"나는 방식으로 운영되고 있습니다. 특히 관광상품화를 목표로 하는 이번 사업 확장 단계에서 **반복 생산 가능한 콘텐츠 자동화 체계의 부재**가 성장을 제약하는 병목입니다.

## WHAT — 구체적으로 무엇이 문제인가?

### 1. 콘텐츠 생산 프로세스의 비체계성

제주소금이 보유한 기술—용암해수의 미네랄 특성, 나트륨·마그네슘 조절 기술, 40만년 전 화산지형의 희소성—은 충분히 매력적입니다. 그러나 이를 **일관된 브랜드 톤, 캐릭터, 스토리라인 없이** 각자 다른 방식으로 표현하다 보니 소비자 입장에서는 "누가 어떤 의도로 이 제품을 만들었는가"가 명확하지 않습니다. 숏폼 콘텐츠, 제품 소개서, SNS 카피, 상세페이지 모두 톤·메시지·비주얼이 제각각이면, 브랜드 신뢰도가 누적되지 않고 매번 "처음 만나는 기업" 취급을 받게 됩니다.

더 근본적인 문제는 **"한 번 만들고 끝나는 구조"**입니다. 현재는 캐릭터를 만들면 그것으로 끝, 숏폼 영상을 기획하면 1~2편만 만들고 이후 재생산 기준이 없습니다. 국내 프리미엄 소금 시장이 736억원 규모이고, 나트륨 과다섭취 이슈(한국인 1일 섭취량 3,699mg vs WHO 권고 2,000mg)로 관심이 높아지는 시장에서, 경쟁사 대비 우위를 지속하려면 **주 1회, 월 4주 단위로 캐릭터·시나리오·네이밍·제품 소개 콘텐츠를 반복 생산**할 수 있는 틀이 필수적입니다.

### 2. AI 기반 자동화 인프라의 부재

현재 제주소금은 콘텐츠를 만들 때마다 "처음부터 기획, 작성, 검수" 전 과정을 수동으로 반복합니다. 이는 인력 비용이 매우 높고, 일관성을 보장하기 어렵습니다. 특히 숏폼 영상(숏페이스, 릴스, 유튜브 쇼츠 등)은 제작 크레우가 필요하고 비용이 더 들기 때문에, 현재로서는 월 1~2편 정도만 가능한 상황입니다.

**AI 기반 자동화 체계**가 있다면, 기업이 자료(제품 스펙, 기술 정보, 마케팅 메시지)만 업로드하면:
- 브랜드 톤에 맞는 캐릭터 설정이 자동 제안되고
- 숏폼 시나리오가 자동으로 생성되고
- 제품 소개서·상세페이지가 자동으로 작성되고
- Higgsfield 같은 AI 영상 생성 도구와 연동되어 스토리 확정 즉시 영상화될 수 있습니다.

이렇게 되면 한 달에 4번 콘텐츠 사이클을 돌릴 수 있고, 비용도 1/10 이하로 줄일 수 있습니다.

### 3. 사업 우선순위(뷰티)와 포커스(식품) 간의 정렬 필요

기업의 사업 영역 우선순위는 **뷰티(1순위) > 헬스케어(2순위) > 식품(3순위)**입니다. 용암해수의 고미네랄·저나트륨 특성은 피부 보습, 미네랄 보충 등 뷰티·건강기능식품으로 확장하기에 이상적입니다. 그러나 이번 프로젝트의 포커스는 **식품(3순위)**이고, 구체적으로는 **관광상품 목적**입니다. 오키나와 벤치마킹—제주 관광객 1,378만명이 방문하는 제주에서 소금 공장 견학·체험·굿즈 판매 모델을 구축하려는 전략입니다.

이는 모순처럼 보일 수 있으나, **단기(3개월)는 식품·관광, 중기(6~12개월)는 뷰티·헬스케어로 수렴**하는 전략입니다. 즉, 이번 콘텐츠 자동화 체계는 "식품 관광상품"부터 시작하되, **같은 구조를 뷰티·헬스케어 라인에도 쉽게 확장 가능**하도록 설계해야 합니다.

## WHERE — 어디서 이 문제가 발생하는가?

### 1. 기업 내부: 콘텐츠 생산 라인의 부재

제주소금은 현재 **기술·제품 개발팀(R&D)은 잘 갖춰져 있으나, 마케팅·콘텐츠 팀은 전무한 상태**입니다. 용암해수 미네랄 조절 기술, 제품 스펙, 안전성 검증 같은 정보는 충분히 있으나, 이를 "소비자 입장에서 매력적인 이야기"로 변환하는 과정이 없습니다. 따라서 현재는:
- 사내 임의의 담당자가 "이 정도면 충분히 좋은 제품이니까"라고만 생각하고 광고 문구를 작성
- 브랜드 정체성, 타겟 세분화, 톤앤보이스 같은 기초가 없음
- SNS, 블로그, 상세페이지 모두 다른 스타일로 표현되어 일관성 부족

### 2. 시장 기회: 타겟층의 니즈와 채널의 성장

**타겟 고객**: 주 타겟 40~60대 여성(관광객, 선물 구매자), 확장 타겟 20~30대(온라인, SNS 중심)  
**채널**: 관광지 체험·굿즈 판매(오프라인), 숏폼 영상(유튜브 쇼츠, 릴스, TikTok), 상세페이지(쿠팡, 마켓컬리 등)

이 모든 채널에서 동시에 "제주소금이란 무엇인가"를 일관된 방식으로 전달해야 하는데, 현재는 각 채널별로 따로 만들다 보니 비용과 시간이 많이 들고, 메시지가 흐트러집니다.

### 3. 기술 기회: AI 및 자동화 도구의 성숙

TimelyAI(Skill/Subagent/Orchestrator 구조의 자동화 플랫폼)와 Higgsfield(AI 텍스트-투-비디오)가 실제 운영 가능 수준으로 성숙했기 때문에, 이들을 조합하면 **최소 인력으로 최대 생산성을 낼 수 있는 구조**가 가능해졌습니다. 이것이 이번 프로젝트의 기술적 기반입니다.

## WHY — 왜 지금 이 문제를 풀어야 하는가?

### 1. 시장의 급속한 변화와 관광 시즌

한국의 프리미엄 소금 시장은 **736억원 규모**이며, 나트륨 과다섭취에 대한 사회적 인식이 높아지고 있습니다. 특히 제주는 연간 관광객 1,378만명이 방문하는 황금의 관광지이며, 오키나와 모델(관광객 + 소금 공장 체험 + 프리미엄 굿즈 판매)을 빠르게 적용할 수 있는 시장 기회가 **지금 바로** 열려 있습니다. 경쟁사(기타 프리미엄 소금 브랜드, 건강기능식품)가 SNS·숏폼 영상 마케팅에서 점진적으로 강해지는 시점에, 제주소금이 **지속적이고 일관된 콘텐츠 공급**을 시작해야 선착 우위를 유지할 수 있습니다.

### 2. 투자자·파트너 신뢰도 확보

제주소금은 2025년 3월 설립된 신생 스타트업이며, 현재 성장 단계입니다. 투자자나 유통 파트너(온라인 마켓, 오프라인 매장)는 "이 회사가 얼마나 브랜드를 체계적으로 관리하고, 지속 가능한 성장을 할 수 있는가"를 평가합니다. **AI 기반 자동화 콘텐츠 체계**를 구축하고 시연하는 것만으로도:
- "이 회사는 기술력뿐 아니라 마케팅 역량도 있다"는 신호 전달
- "대규모 인력 없이도 지속적 성장이 가능하다"는 스케일러빌리티 증명
- "향후 뷰티·헬스케어로 빠르게 확장할 수 있는 기초가 마련됐다"는 신뢰 구축

### 3. 팀의 역량과 기한의 정렬

이번 Upstage 부트캠프 팀("으랏차차 짠돌이네", 박주미·고수아)은 **4영업일이라는 짧은 기한 내에 이 문제를 해결할 역량이 입증된 상태**입니다. 이 기회를 잃으면:
- 제주소금이 자체적으로 이 시스템을 구축하려면 6개월~1년, 비용 수억원대
- 부트캠프라는 "공식 교육 + 멘토링 + 인프라" 지원 구조를 다시 활용하기 어려움

따라서 **지금 이 팀, 지금 이 기한에** 이 문제를 풀어야 합니다.

## HOW — 어떤 방식으로 접근할 것인가?

### 우리 팀의 강점과 차별점

#### 1. 듀얼 아웃풋 구조 (AI Harness + 웹앱)

보통의 "콘텐츠 생산 자동화" 프로젝트는 **"템플릿 도구"** 수준에서 멈춥니다(예: "이 양식에 정보를 넣으면 블로그 글이 만들어집니다"). 우리가 하는 것은 그것이 아니라:

1. **AI Harness(TimelyAI 등록)**: Skill/Subagent/Orchestrator 구조로 **5가지 콘텐츠(캐릭터, 숏폼, 네이밍, 제품 소개, 상세페이지)를 자동 반복 생산**하는 에이전트 체계. 이것은 "제주소금이 언제든 꺼내 쓸 수 있는 실제 운영 도구"입니다.

2. **웹앱(Claude Code + 서브에이전트)**: 제주소금 직원이 매일 아침 시스템에 접속하면, 자료(보도자료, 신제품 정보, 마케팅 메시지) 업로드 → 자동 카테고리화 → 관리자 승인 → 캐릭터+영상 유형 선택 → 스토리 자동 추천 → 확정 → Higgsfield 자동 영상화까지 모두 "클릭 몇 번"으로 가능합니다.

이는 단순 "조언"이 아니라 **실제 제주소금이 쓸 수 있는 동작 가능한 소프트웨어**입니다.

#### 2. 브랜드 라인 + 제품 라인의 병렬 구조

보통의 팀은 "다 함께 여러 일을 순차적으로" 하다가 시간을 낭비합니다. 우리는 **GitHub 브랜치 기반으로 2개 라인을 병렬 작업**합니다:

- **브랜드 라인** (박주미): 캐릭터 설정(소금·용암해수), 숏폼 시나리오, 네이밍 → 이미지·톤 정의
- **제품 라인** (고수아): 제품 데이터 정리, 제품 소개서, 상세페이지, 데이터 구조 설계 → 실제 동작 구현

각각이 TimelyAI 또는 웹앱의 다른 부분을 담당하되, 최종 orchestrator에서 통합됩니다.

#### 3. brand-voice.md 기반의 철저한 일관성 관리

우리가 설정한 **톤앤보이스 3원칙** (정직함 / 제주+기술의 만남 / 일상 속 함께함)을 모든 콘텐츠의 "체크리스트"로 삼습니다. 특히 **절대 금지 사항** (근거 없는 의학 표현, 과도한 유행어, 자극적 비교)을 위반하는 콘텐츠는 compliance-reviewer-agent가 필터링합니다. 이렇게 하면 4주마다 콘텐츠를 만들더라도 "브랜드로서의 정체성"이 무너지지 않습니다.

#### 4. 4영업일 내 "작동 가능한 프로토타입" 완성

많은 팀이 "이상적인" 시스템을 설계하다가 시간을 초과합니다. 우리는:
- **8/3**: 콘텐츠 Skill 5개를 "실제로 TimelyAI에 등록"할 수 있는 수준으로 완성
- **8/4**: 웹앱의 핵심 4개 기능(업로드·분류·승인·영상화)을 프로토타입 수준으로 완성 + Higgsfield 데모 1편 생성
- **8/5**: 다듬기만 (UI, 검수)

즉, "언젠가 써 볼 수 있을 것 같은 설계 문서"가 아니라 "내일부터 쓸 수 있는 실제 도구"입니다.

| **출력** | • 선택된 탭의 자료 목록이 화면에 표시됨<br/>• 각 자료 항목에서 "이거로 스토리 만들기" 버튼 가능 |
| **내일 완성도** | 3개 탭이 시각적으로 보이고, 탭 클릭 시 자료 필터링만 작동하면 OK / 세밀한 디자인은 Day3에 |
| **담당** | frontend-agent (UI 컴포넌트: CategoryTabs) |

### **기능 3: 관리자 모드 (자료 편집, 비밀번호)**

| 항목 | 내용 |
|---|---|
| **입력** | 관리자 비밀번호 (간단한 숫자나 문자열, 실제 보안 아님) |
| **프로세스** | • 비밀번호 입력 후 로그인 (로컬 상태만, 실제 서버 인증 아님)<br/>• 기능1~2에서 업로드된 자료들을 편집/삭제 가능<br/>• 예: "나트륨 24.1g" → "나트륨 22.5g"로 수정 후 저장 |
| **출력** | • 수정된 자료가 다시 저장됨<br/>• 기능2의 탭 뷰에서 수정된 내용 즉시 반영 |
| **내일 완성도** | 비밀번호 한 개만 있으면 됨 (다중 계정 같은 복잡한 건 스킵) / 수정 기능은 아주 기본적으로만 |
| **담당** | frontend-agent (UI 컴포넌트: AdminMode) + backend-agent (수정 로직) |

### **기능 4: 캐릭터 + 자료 + 영상유형 선택 → 스토리 추천 → 힉스필드 연동**

| 항목 | 내용 |
|---|---|
| **입력** | • 캐릭터 선택 (결이 / 용암이 / 해수 / 미내 / 현무 / 가마할방 / 불이 / 한라)<br/>• 자료 선택 (기능2에서 본 목록 중 1개)<br/>• 영상유형 선택 (예: "제품 소개", "캐릭터 스토리", "교육용" 등 3~4가지) |
| **프로세스** | • backend-agent가 "캐릭터 + 자료 + 영상유형" 조합을 brand-voice.md 기준으로 **스토리 자동 추천**<br/>• 예: "결이" + "프리미엄솔트" + "제품 소개" → "우리 함께라면 뭐든 할 수 있어! 제주에서 나온 소금으로 우리 가족 밥상을..." 같은 스토리 텍스트 생성<br/>• **사용자가 스토리 수정 가능** (필요하면)<br/>• 확정 버튼 클릭 시 **Higgsfield 자동 연동**: 스토리 → 영상 생성 요청 |
| **출력** | • 스토리 텍스트 표시 (수정 가능)<br/>• "확정" 버튼 클릭 후 Higgsfield 연동 시작<br/>• 영상 생성 완료 시 "동영상 준비됨" 알림 |
| **내일 완성도** | • 스토리 추천은 **template 기반으로 간단하게** ("캐릭터명 + 제품명 + 한두 줄 메시지" 정도)<br/>• Higgsfield 연동은 API 자리만 만들고 (실제 키는 없어도 OK), 테스트는 수동으로<br/>• 에러 핸들링은 최소 (아주 기본 에러만) |
| **담당** | backend-agent (스토리 추천 로직) + frontend-agent (UI: StoryToVideoFlow) + database-agent (선택지 관리) |

## 최종 결론: PRD v1.0 확정

이 PRD는 **다음을 보장합니다:**

1. **기업 문제의 정확한 이해**: 콘텐츠가 없는 게 아니라 "일관성 부재"와 "반복 생산 불가능" 구조가 진짜 문제

4. **타겟별 전략**: 5개 오디언스 그룹 각각에게 맞춤화된 메시지
5. **4영업일 완성 확신**: 프로토타입 수준으로 정의함으로써 Over-engineering 방지

- "문제: 일관성 부재" → 이 PRD Step1~3의 분석으로 설득
